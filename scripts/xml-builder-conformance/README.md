# XML builder conformance

Private controls for `vfast-xml-builder`: fast-xml-builder **1.3.1**,
fast-xml-parser **5.11.2**, and @nodable/entities **3.1.0**, checked October 30, 2026.
The `legacy-entities` alias pins @nodable/entities **2.1.0** solely for an upstream
test that uses that version's no-option encoder constructor. The current parser
uses 3.1.0. Storage **8.4.0** comes from the adjacent retry-request fixture.
These packages and snapshots are excluded from runtime archives.

```sh
npm --prefix scripts/xml-builder-conformance ci --ignore-scripts --no-audit --no-fund
node scripts/xml-builder-conformance/run.cjs --upstream
node scripts/xml-builder-conformance/run.cjs
node scripts/xml-builder-conformance/regressions.cjs
node scripts/xml-builder-conformance/callers.cjs --upstream
node scripts/xml-builder-conformance/callers.cjs
node scripts/xml-builder-conformance/bundles.cjs
```

Repeat with Bun. Root tests include the retained cases and paired regressions;
the integration gate exercises actual callers. CI also runs upstream controls
and browser bundle execution on both runtimes.

## Retained evidence

`upstream/` retains release commit
`d7d1d7b7e1ed90474b026d564f3ec7057a35fdec`: all 16 spec files, source/declarations,
license, package metadata and the options reference. Files have `.txt` extensions
and normalized trailing EOF whitespace. The runner verifies SHA-256 for every
snapshot, exact installed source identity and the comparison versions.

An assert-backed Jasmine-style adapter executes all **136 cases**. Imports are
provided in memory; no expected results are changed. The one `xit` is enabled:
its known ordinary-vs-ordered newline expectation still fails on both builders.
The runner requires that exact case identity and independently checks the actual
ordinary formatted string. Thus 135 enabled cases pass and one upstream-disabled
inconsistency is recorded, with no skipped cases. Prototype descriptors are
restored after each test because an upstream test modifies `Object.prototype`.

`regressions.cjs` compares 17 cases where upstream and VPM differ: root arrays,
null order, Date arrays, regex/ordered filtering, ordinary/ordered raw depth,
empty-node boundaries, invalid sanitizer output, duplicate text processing,
null-prototype grouping, object-value escaping, option snapshots, callback views,
inherited text, attribute predicates and invalid budgets.

The package's 17 focused tests additionally cover cycles and reuse, shared
subtrees, depth matrices, callback reentry, option contracts, grouped/raw filters,
sanitizer contexts, custom regex state, comment/CDATA delimiters, 4,000 generated
escaping comparisons, parser round trips and CJS/ESM identity.

## Real callers and browser output

`callers.cjs` copies the parser's actual source to a temporary directory, changes
only its two builder re-exports, and counts calls through the replacement. The
published parser's bundled builder cannot be substituted by merely aliasing its
dependency. Nine differential cases cover ordinary/ordered objects, attributes,
groups, CDATA/comments, stop nodes, formatting, sanitization and Storage-shaped
arrays. Two parser-to-builder round trips also run.

Storage's actual multipart uploader completes one-part and three-part uploads.
Eight mocked HTTP requests check part bodies, MD5 hashes, escaped ETags and sorted
completion XML. Each upstream/VPM run records 13 constructions and 13 builds;
the uploads account for two of each. Network transport is mocked; XML construction
and SDK code run. This demonstrates the exercised API paths, not an application
migration or a complete Storage SDK replacement.

`bundles.cjs` builds the package's native ESM entry for the browser with Bun and
executes it in an isolated VM, including naming, matching and escaping. The
generated byte count depends on the bundler version.
