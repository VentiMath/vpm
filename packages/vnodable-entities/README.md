# vnodable-entities

Single-pass XML/HTML entity decoding, configurable registration and expansion
limits, and named/XML-safe encoding. The API baseline is **@nodable/entities
3.1.0**, checked October 30, 2026. Zero runtime dependencies; CommonJS and ESM,
tested on Node 24 and Bun.

```js
const {EntityDecoder, EntityEncoder, COMMON_HTML} = require('vnodable-entities');
const decoder = new EntityDecoder({namedEntities: COMMON_HTML});
decoder.decode('&lt; &copy; &#65;');          // '< © A'
decoder.decode('&#65junk;');                 // unchanged: malformed reference
const encoder = new EntityEncoder({encodeAllNamed: false});
encoder.encode('<hello> & goodbye');         // '&lt;hello&gt; &amp; goodbye'
```

ESM provides the same named exports. Named encoding requires an explicit table,
for example `new EntityEncoder({namedEntities: COMMON_HTML})`. There is no default
export. Non-string encode/decode inputs pass through unchanged.

## Decoder

The default table contains the five XML entities. `namedEntities` adds or
overrides base entries. Lookup priority is document input, persistent external,
then base. `setExternalEntities(map)` replaces persistent entries;
`addExternalEntity(name, value)` adds one. `addInputEntities(map)` replaces the
current document's entries and resets its counters **only after successful
registration**. `reset()` clears document entries/counters, keeps external entries,
and restores the constructor's XML version. `setXmlVersion(number)` selects 1.1
only for numeric `1.1`; other values select 1.0, matching the parser's API.

Registration copies own enumerable keys. String values and legacy `{val: string}`
objects work; `regex`/`regx` fields are ignored and callable values are skipped,
never executed. Names must be nonempty and exclude reference delimiters,
whitespace and upstream's reserved characters. This is not XML Name validation.
Replacement values may contain literal ampersands: all registration methods now
handle them consistently, and returned replacement text is never scanned again.
Names and numeric references are not truncated at the old 32-character window.

`onExternalEntity` and `onInputEntity` run at registration and must synchronously
return `ENTITY_ACTION.ALLOW`, `BLOCK` or `THROW`. Unknown decisions throw. Failed
validation, getters or hooks cannot partially replace maps or reset counters.
Reentering the decoder from a registration getter/hook or `postCheck` throws.
External side effects performed by application callbacks cannot be rolled back.

`postCheck(resolved, original)` runs once on every string input, including plain
and empty text, and must return a string. Returning `original` can reject the
result; attempted expansions remain charged. The decoder does not inspect or
limit arbitrary content generated by this application callback.

`remove` and `leave` arrays match exact reference tokens without `&`/`;`. Remove
wins, including for numeric references, and user-directed removals count as the
external tier. Null arrays are empty; non-string entries are ignored for upstream
compatibility. Explicit leave rules also take precedence over NCR policy.

### Numeric references and budgets

Decimal and `x`/`X` hexadecimal references require every digit to be valid. Junk,
signs, spaces, empty digits and out-of-range values remain literal. The uppercase
`X` extension is retained; this codec is not a complete XML well-formedness checker.

`ncr.onNCR` accepts `allow`, `leave`, `remove`, or `throw`. Nulls, surrogates,
U+FFFE/U+FFFF and prohibited XML 1.0 C0 controls have a minimum `remove` action;
`throw` is stricter. XML 1.1 permits non-null C0 references. Supplementary Unicode
noncharacters remain allowed by the XML Char productions. `nullNCR` can strengthen
the null action; legacy `allow`/`leave` values clamp to removal.

`numericAllowed: false` leaves otherwise permitted references literal while
still applying prohibited-character handling. The current XML parser forwards
its `htmlEntities` object here; that truthy entity-map form remains supported.

`limit.maxTotalExpansions` counts replacements and `limit.maxExpandedLength`
counts cumulative positive growth in UTF-16 code units. Limits accept nonnegative
safe integers, with **0 or Infinity meaning unlimited**; NaN, negative, fractional
and unsafe finite limits reject. `applyLimitsTo` accepts `external` (default),
`base`, `all`, or an array of `external`/`base`. Numeric references are base-tier
operations. Counters persist across calls; attempted replacements are charged
before output is appended, including when a limit or post-check rejects a call.
These are expansion budgets, not total input/output size or DTD nesting limits.

## Encoder and tables

`encodeXmlSafe` defaults to true and controls the five XML punctuation characters.
`encodeAllNamed` defaults to true and requires `namedEntities`. Named matching
uses longest-prefix selection, supports ASCII and arbitrarily long custom values,
and keeps the last inserted name when multiple entries have the same value.
XML punctuation follows `encodeXmlSafe`, taking precedence over named mappings.
Other ASCII characters can now be named-encoded when present in the selected map.

`maxReplacements` is cumulative until `reset()`; 0/Infinity means unlimited. When
a finite quota is reached, the remaining text is returned literally, preserving
upstream behavior. A quota-limited encoder therefore does not promise fully
escaped output. Options/counters are read-only views of private state; the legacy
`trie1`, `trie2` and `trie3` inspection maps are independent copies. Frozen maps
containing only data properties can share a compiled trie; mutable/accessor maps
are compiled independently. Custom prefix-heavy maps can increase matching work.

All **15 categorized tables** and **932 combined names** are retained, with four
standard-name corrections: `ocirc → ô`, `boxDl → ╖`, `boxdL → ╕`, and
`af → U+2061`. The 23 upstream nonstandard aliases remain available. These tables
are a subset with extensions, **not the complete HTML5 entity vocabulary**.
Tables are frozen; ESM bundles can discard unused categories. XML-only decoding
and encoding do not require the combined table.

## Evidence

[Retained tests and callers](../../scripts/nodable-entities-conformance) include
all 246 upstream cases, three explicit ASCII-encoding expectation changes,
19 paired upstream/VPM discriminators and 17 focused tests. Independent checks
cover every Unicode code point in both XML versions and 10,000 generated encoder
inputs. Real fast-xml-parser **5.11.2** source covers ordinary/DTD entities,
attributes, limits, hooks and parser reuse. Storage **8.4.0** completes two mocked
multipart uploads through that parser, including escaped object keys.

[Benchmarks](bench/results/README.md) retain raw samples, controls, source hashes
and regressions. Browser bundle tests execute XML-only, full-table and encoder-only
outputs and verify unused tables disappear. These checks do not migrate the
application or establish an end-to-end application speedup.

The rules are grounded in [XML 1.0](https://www.w3.org/TR/xml/#NT-Char),
[XML 1.1](https://www.w3.org/TR/xml11/#NT-Char), and the
[HTML named-reference table](https://html.spec.whatwg.org/multipage/named-characters.html).
MIT attribution and source metadata are retained in [LICENSE](LICENSE) and
[PROVENANCE.json](PROVENANCE.json).
